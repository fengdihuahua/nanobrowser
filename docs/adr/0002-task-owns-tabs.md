# ADR 0002：任务拥有标签页，分组只是视图

- 状态：已采纳
- 日期：2026-11-04
- 相关：[design.md](../design.md) §2.1、§2.2；[roadmap.md](../roadmap.md) H8、N8–N10

## 背景

需求：在扩展里对"当前页面"发起任务，并且**这个页面属于这个任务**；调试时能按任务分组，一眼看出哪些标签页属于哪个任务。

三个事实：

1. layer 早就支持一个会话持有多个标签页：`Session.shareTab`、`adoptTab`，页面用 `window.open` / `target=_blank` 打开的标签会自动加入持有者的会话。
2. Hub 的 `LeaseManager` 是**一个客户端一个标签页**，所以"任务拥有多个页"在租约层做不到。
3. 旧产品确实按会话给标签页分组，验收检查还在：`src/background/checks/panel-tabs.ts`（agent 打开的标签在后台入组、`@` 共享、拖出、删除会话时清理）。分组能力随旧面板一起被删了，`tabGroups` 权限也不再申请。

## 决策

- **归属**：任务（会话）→ 标签页集合，记在 Hub 租约里（1:N），每张标签页同一时刻只有一个 owner。
- **分组**：Chrome 标签组是**视图**，不是归属。用户把标签拖进拖出组，不改变归属。
- **生命周期**：第一个标签加入时建组；页面打开的标签自动入组；标签离开会话时移出；任务结束可解散空组。
- **跨窗口**：一个组只能在一个窗口，跨窗口任务每窗口一个组，颜色与标题一致。
- **拖出组不等于移出任务**：归属只看租约；要让页面离开任务，走显式的"从任务移除"。
- **任务结束**：默认保留标签页、解散组，绝不关闭用户自己的页面；任务自己打开的页面可以通过显式的"关闭本任务的页"清理。

## 被否决的方案

| 方案 | 否决理由 |
|---|---|
| 分组即归属（看用户在哪个组判断 owner） | 用户拖一下标签就悄悄转移了控制权，无法审计 |
| 一个任务一个标签页 | 处理不了 `target=_blank`、`window.open`、多页对照调试 |
| 不做分组 | 多任务并行时无法分辨页面归属；旧产品的体验倒退 |

## 后果

- `LeaseManager` 改成客户端 → 标签页集合；`ownerOf(tabId)` 仍然是唯一性检查点；`detach` 是整体释放还是移除单个，需要定（见 roadmap N2/H8）。
- 系统提示里的 "This session owns tab X" 要改成"拥有这些标签页"。
- 面板需要任务 → 标签页的 chips（旧 `panel-tabs` 检查描述了期望行为）。
- `tabGroups` 权限要重新申请，并同步 `PRIVACY.md` 与商店文案。
- 页面打开的标签要同时满足三件事：layer 收养、Hub 租约加入、标签组加入——三者缺一，归属就会漂。
