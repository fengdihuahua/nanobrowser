# ADR 0005：recipe 就是 JSON，手写痛苦用工具解决，不换格式

- 状态：已采纳
- 日期：2026-11-04
- 相关：[design.md](../design.md) §7.1；[roadmap.md](../roadmap.md) S12、S13

## 背景

一个 一个 21 步的技能，手写 `recipe.json` 很痛：每步 `{id, tool, args, target}`，引号、逗号、缩进都要对。于是提出过三种替代：YAML、`SKILL.md` 里嵌可执行块、或者干脆只录制不手写。

同时还有一个相关的问题：**dry run 要不要判断言**。直觉上"预检应该告诉我断言会不会过"，但断言描述的是**这一步之后**的页面，dry run 不执行这一步，页面还停在之前——它看不见那个结果。

## 决策

**1. recipe 保持 JSON。** 不引入 YAML，也不在 `SKILL.md` 里嵌可执行块。

- JSON 是**已经能 diff、能 review、能被 `validateRecipe` 完整校验**的格式；YAML 带来的缩进歧义（尤其是中文内容与多行文本）会把"手写痛苦"换成"静默解析错"。
- 内嵌块会让 `SKILL.md` 同时是散文和执行体，这正是 ADR 0001 分开的两样东西。
- 手写痛苦的正确解法是**让机器写初稿**：录制器现在会推断参数、把固定等待改成条件等待、丢掉 ref。手改只该是修几处目标。

**2. dry run 不判断言。** 它只做它能真回答的事：解析每一步的目标在不在。

- 断言在 dry run 里评估必然是误报：写操作之后才出现的文本，此刻当然不在。
- 断言的**形状**由 `validateRecipe` 校验（缺 `after`、没判据、指向不存在的步都会报 `INVALID_RECIPE`），这一层已经覆盖了"写错"的情况。
- 真要在预检里判断言，只能靠"这一步假设已经发生"的模拟，那是另一个功能，不是 dry run。

## 被否掉的

- **YAML**：解析歧义 + 需要新依赖；收益只是省几个引号。
- **`SKILL.md` 内嵌代码块**：散文与可执行体混在一份文件里，冲突 ADR 0001。
- **只录制不手写**：录制器不知道"为什么这一步要等"，SOP 的价值就没了。
- **dry run 模拟断言**：等于假执行一遍，读起来像真的，写起来比真的更容易错。

## 后果

- `docs/reference.md` §5 是 recipe 的唯一格式说明，`validateRecipe` 是唯一校验点。
- 手写体验的改进走"录制器更聪明"这条路，不再讨论换格式。
- roadmap 里不再有"书写格式"这一项；S13 以"决定不做"关闭，理由记在这里。
