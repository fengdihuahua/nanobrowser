# ADR 0004：MCP 是能力面，不是第二个前端

- 状态：已采纳
- 日期：2026-11-04
- 相关：[mcp.md](../mcp.md) §1–§4；[design.md](../design.md) §2；[roadmap.md](../roadmap.md) M1–M8

## 背景

要让别的 agent（Qoder、Claude Code、Cursor……）也能用这套东西，最省事的想法是"把 DSH 插件的工具面对齐到 MCP"。问题在于：DSH 插件的一半价值不在工具，而在**上半身**——系统提示、live 局面、技能目录、页面上下文、抽屉审批、录制。

硬要对齐会得到两个结果：要么把 DSH 的提示塞进别人的模型（做不到），要么在适配器里再造一套"半像不像"的提示（错误的承诺）。

## 决策

**MCP 只翻译协议、暴露能力；策略全部留在 Hub 和扩展。**

- 适配器做的事：注册成一个 Hub 客户端、转发 18 个浏览器工具、提供 `attach`/`detach` 两个控制工具、提供技能三个工具（`skill_list`/`skill_show`/`skill_run`），以及在 `initialize` 里给出六条规则。
- 适配器**不做**的事：不做提示注入、不做 live 局面、不做技能目录（改用工具）、不做录制、不申请/解释审批（审批在扩展卡片上）、不做 `wait_for_user`（没有抽屉就没人按 Continue）。
- 租约的**强制**在 Hub：无租约的动作调用被拒，适配器只是申请者。
- 技能读的是同一份目录、跑的是同一个 `core/run.js`，所以两边录的技能互为可用。
- 命名暴露裸名（`click`），前缀由客户端自己加；适配器不加。

## 只承诺"能跑"，不承诺"一样聪明"

- **A 能跑**：外部 agent 用我们的工具执行同一份 recipe，审批仍在侧边栏。✅
- **B 一样聪明**：同等上下文、接管能力、判据。❌ 不可达——对方的模型、提示和循环是它自己的。

这条写死在文档里，是为了以后不再反复讨论"为什么 Claude Code 跑得没 DSH 好"。

## 被否掉的

- **Hub 直接说 MCP**：会把传输层塞进 Hub，破坏"队列 / 租约 / 审计"的边界，也让 Hub 依赖某个协议的版本。
- **在适配器里复制 DSH 的提示**：抄不全，还会和 `host/prompt.js` 漂移。
- **给每个客户端一套专用适配**：一个标准适配器 + 客户端自己的上半身，已经够用。
- **把 skills 做成 MCP prompts/resources**：prompts 是"用户选的模板"，不是 agent 自己发现的知识；硬套是发明映射。

## 后果

- 适配器的错误必须自己说人话（"没有 Hub 在听"、"令牌不对"、"这页被别人占着"），因为对面没有 DSH 的提示兜底。
- 适配器的测试必须**真的 spawn 一个进程**说 JSON-RPC——否则协议层的问题只有在用户那里才暴露。
- 任何"让 MCP 更聪明"的想法，先问：它能不能只靠工具和 Hub 策略实现？不能就不做。
